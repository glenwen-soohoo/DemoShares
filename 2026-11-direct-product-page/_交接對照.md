### 容易記錯的三個

1. **規格說明與保存方法是同一個欄位。** 資料表只有 `Product.Remarks` 一欄，用字串 `split` 把前後段隔開。後台編輯頁才拆成兩個 textarea。
2. **後台 ViewModel 名字跟資料表不一樣。** `LargeDiscount` ↔ `MultiBoxDiscount`、`ProductDelivery` ↔ `DeliveryMessage`、`Specification` ↔ `Remarks` 前段。寫 SQL 用資料表名，改後台 view 用 ViewModel 名。
3. **子分類是 `Product.Type2`，不是 `ProductDetail.Type2`。** 產線是 `Product.Type`。

## C. 這兩頁 demo 是什麼

**前台是現況的 1:1 還原，還沒有這次需求的新區塊**（重點區、副標題要疊在這個底上）。

**後台在 1:1 還原的底上做了兩件事**：加進這次需求的新欄位，以及把整張「產品基本資訊」卡照用途重新分區。分區細節見 D 節。

| 頁 | 怎麼做出來的 |
|---|---|
| `direct-product-detail(ItemDetail).html` | 線上 `greenbox.tw/Products/ItemDetail/74987` 未登入版的 markup，CSS 直接連真站那 14 支樣式檔（絕對網址）。**截到「喝湯抽大獎」那張 banner（`.adArea`）為止**，後面的商品描述與平台保證沒有還原。真站 script 全移除，頁尾補了兩小段代打：商品主圖輪播（jQuery + slick，主圖與縮圖 asNavFor 連動）與規格切換 |
| `direct-product-edit(Edit18).html` | `Edit18.cshtml:105-462` 的「產品基本資訊」卡逐字還原，Razor 換成靜態值。那一頁實際載的 10 支 CSS 打包在 `assets/`。外殼（header、左側選單）沿用加購品 demo 那一套，樣式在 `assets/11-gox-shell.css` |

兩頁都用真 class，所以連上真 CSS 就自動對。**要加新功能請沿用這些 class 往上疊，不要另外自刻一套結構**，自刻的 class 連了真站 CSS 也不會被套到。

### 這兩頁沒有還原的部分

| 沒還原的 | 為什麼 |
|---|---|
| 前台的商品描述、平台保證（banner 以下） | 不在這次需求範圍，截掉了 |
| 後台的 `_ProductTagBlock`、產品規格設定（React 掛載點）、產品圖片／商品描述／產地故事／追蹤碼設定四張卡 | 不在這次需求範圍，頁面上標成佔位 |
| 前台的購物車 API、追蹤碼、lightbox 點圖放大 | script 全移除。輪播與規格切換有補代打，其他只有外觀 |

### 前一版（已歸檔）

`direct-product-detail-v1(archived).html`、`direct-product-edit-v1(archived).html` 是第一版，外殼與色票沿用設計端的示意稿、不是真站的值，所以重做。
那一版裡有重點區四格、副標題、產季四層色條、大小對照與測試台九個情境的互動邏輯，疊新功能時可以回去抄。

## D. 後台這一版的分區

真站「產品基本資訊」是一張卡裝三十幾個欄位，沒有任何分隔。這一版照用途切成八組，每一組是一個可收合的區塊。
**分區不改任何欄位的 name、型別或存檔行為**，只改擺放位置與加群組標題，所以 ViewModel 與 ProductModel 的存取都不用動。

| 區塊 | 框色 | 收合行為 | 裝什麼 |
|---|---|---|---|
| 基本 | 灰 | 預設展開 | 產品名稱、類別、快速到貨-類別、排序 |
| 產地直送設定 | 綠 | 類別＝產地直送才展開 | 產地、小農、食農卡片、副標題、產季、大小對照、上架提醒事項 |
| 檢驗報告 | 灰 | 預設展開 | 第三方、無毒農，各自帶到期日 |
| 商品文案 | 灰 | 預設展開 | 規格說明、保存方法、置底商品標示、貼心叮嚀、多盒優惠、溫層配送、產品描述、產品關鍵字、部落格連結 |
| 販售規則 | 灰 | 預設展開 | 含運費、假單品、免稅、前台隱藏、只在 app 顯示、限定購買規則、限購數量總和、購物車搶購 |
| 通知文案 | 灰 | 預設展開 | 簡訊內容、延遲出貨簡訊 |
| 物流與倉儲 | 灰 | 預設展開 | 配送溫層、儲位庫號／架號／編號、產品國際條碼 |
| 前台顯示 | 灰 | 預設展開 | 標籤、產品圖標籤、產品基本銷售數 |
| 前台重點區預覽 | 綠 | 類別＝產地直送才展開 | 不是欄位，讀上面的保存方法、貼心叮嚀、多盒優惠 |

綠框代表「選了產地直送才用得到」，灰框代表「每條產線都要填」。

### 分區順手解掉的三件事

| 原本 | 這一版 |
|---|---|
| 規格說明與保存方法是同一個資料欄位 `Product.Remarks` 的前後兩段（中間用字串 `split` 隔開），卻分在左右兩欄、中間隔了四五個欄位 | 並排在商品文案的第一列 |
| 「溫層配送」（`ProductDelivery`，自由文字）與「配送溫層」（`TemperatureTypeId`，下拉常溫／冷藏／冷凍）名字只差字序，擺得又遠，選錯沒人會發現 | 拆到不同區塊：文字那個進商品文案，下拉那個進物流與倉儲 |
| 上架提醒事項（`RemindText`）被包在 `id="ImgSideContext"` 的 `display:none !important` 裡，後台改不到，但前台 `ItemDetail.cshtml:181` 會讀它印出「預計 ○○ 採收」 | 拿出來放進產地直送設定。**要不要讓營運編輯請工程與營運決定**，前台的條件是 `ProductType == 0 && ProductSubType == 6`，也就是類別＝產地直送且快速到貨-類別＝不顯示 |

### 這一版拿掉的兩項

| 拿掉的 | 為什麼 |
|---|---|
| A/B Test副產品Id（`OptimizeTestProductIdList`） | 只進不出。`ProductModel.cs:353-355` 讀出來顯示、`:1631-1635` 存回去，就這樣；前台、Service、API、`react-component-export` 都沒有任何地方讀它，營運填了不會發生事。**正式拿掉之前要先查資料表裡有幾筆非空值** |
| 電腦版／手機版圖側文字（`ImgSideContextWeb` / `ImgSideContextMobile`） | 真站這兩欄自己也是 `display:none`，外層容器還整組 `display:none !important` |

### 外殼的已知落差

後台殼的左側選單沒有圖示。`03-bucket-style.css` 會去 `@import` 三支字型檔（`css.css`、`css2.css`、`bucket-ico-fonts.css`），
那三支連同 24 支 `.woff` / `.ttf` 沒有打包進 `assets/`，所以 console 會看到三個 404。
這是外殼層的落差，加購品 demo 也一樣；內容區的欄位不受影響，所以沒有為了圖示把約 1MB 的字型檔放進這個公開 repo。
