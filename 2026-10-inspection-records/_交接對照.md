### 前端條碼辨識（React 元件裡要搬過去的邏輯）

demo 寫在 `data.js`，正式版放 `react-component-export` 的共用 util（建議 `src/utils/barcode/`），電腦版、手機版共用。**正式站前端沒有任何條碼辨識**（fruit_web、react-component-export 都查不到 html5-qrcode／BarcodeDetector／quagga）。後端有 ZXing.Net（見 A 區），目前只用來產生條碼。**已定不做後端備援辨識**，前端辨識不到就手動輸入（2026-10-06）。

| demo 裡（data.js） | 建議命名 | 做什麼 |
|---|---|---|
| `compressImage(file)` | `compressImage` | 上傳前縮到長邊 1280px JPEG（品質 0.8），先鋪白底（透明 PNG 轉 JPEG 會變黑）；**同時記住原檔**，辨識要用原檔 |
| `detectBarcode(src)`／`detectFromFile(file)` | `detectEan13(file)` | 對外只有這一支：載入原圖（長邊上限 4096）→ 先 `scanCanvas` → 解不到再 `detectTiled`。只回 13 碼且檢查碼正確的結果，沒有就回空字串 |
| `scanCanvas`／`scanRow`／`eanFromBits` | 同名，私有 | 自寫的 EAN-13 掃描線解碼：40 條水平線找左右邊界，切 95 等分取覆蓋率加權深淺再查編碼表。專門救「低解析度但乾淨」的圖（螢幕截圖），`html5-qrcode` 讀不到這種。用「剛好約 30 條黑線」先篩邊界組合，避免雜訊照片變慢 |
| `detectTiled`／`regionsOf`／`rotate90` | 同名，私有 | 切格交給 `html5-qrcode`：整張 → 2×2 → 3×3 → 4×4（每格多留一半），再轉 90 度跑整張、2×2、3×3，找到就停。救「條碼只佔照片一小塊」的實拍照 |
| `detectOne` | 同名，私有 | 單格辨識：有 `BarcodeDetector`（Android Chrome）先用，沒有或讀不到用 `html5-qrcode` `scanFile` |
| `startLiveScan(elId, onCode)` | `useLiveBarcodeScan` hook | 「開相機掃條碼」：`Html5Qrcode.start`，`experimentalFeatures.useBarCodeDetectorIfSupported`。失敗分 `denied`（沒權限）／`nocamera`，提示改用選圖片。需要 HTTPS |
| `useBarcodeScan`（兩頁各一份） | `useBarcodeScan` hook | 兩顆只讀條碼、不存照片的按鈕：開相機掃條碼、選圖片辨識 |

`html5-qrcode` 要加進 `react-component-export` 的 dependencies（demo 是內嵌 `html5-qrcode.min.js`）。

### 畫面規則（前端顯示用，不影響資料）

| demo 裡 | 規則 |
|---|---|
| `buttonRows(r)` | 手機版按鈕排三行：①狀態（待檢驗／檢驗中／複驗中；完成區的「移至檢驗區」、暫停區的「恢復至檢驗區」都是切待檢驗）②僅儲存、上傳&儲存 ③移至暫停區、刪除。空的行不顯示。電腦版不用它，三個分頁各自排欄位（03〈列表〉） |
| `canDelete(r)`／`softDelete(no)` | `POST /GoX/InspectionRecord/Delete`（待新建）；欄位 `IsDeleted`、`DeleteTime`、`DeleteUserId` | 軟刪除（2026-10-06）。只有從來沒確認完成過的可以刪（沒有上架時間、也沒有下架時間）；進過完成區、移回檢驗區的也不能刪。所有查詢都要排除 `IsDeleted = 1`；紀錄編號流水號照樣算刪掉的 |
| `canSwitch(r, target)` | 按鈕 disabled 的判斷：在 `allowedNext` 裡，而且切上架或下架時 `missingForComplete` 是空的。後端 `SetStatus` 要再驗一次 |
| `actionLabel(r, target)` | E 版按鈕名：上架＝「上傳&儲存」；下架＝「僅儲存」；擱置＝「移至暫停區」；待檢驗＝「待檢驗」（從擱置是「恢復至檢驗區」，從完成區是「移至檢驗區」）；複驗中＝「複驗中」（只有檢驗區手動切）；檢驗中＝「檢驗中」。⚠ 只是顯示名稱，不要存進 DB |
| `statusText(r)` | 手機版標籤：待檢驗、檢驗中、複驗中；完成區一律「已完成」（另加「顯示於前台」標籤）；擱置是「暫停中」 |
| `ITEM_COLOR`／`RESULT_MARK` | 項目色點（藍紫青咖啡金）、結果勾叉（陰性綠勾、不合格紅叉）；「不選」「未填」灰字。見 03〈編輯〉 |
| `ITEMS`／`RESULTS`／`STORAGES` | 選單選項：五個檢驗項目、陰性／不合格、冷凍／冷藏／常溫。建議做成後端 enum 或常數，前端從 API 拿 |
